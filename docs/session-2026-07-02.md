## 작업 1: 스켈레톤 UI + 페이드인 애니메이션

### 배경
레시피 첫 로드 시 빈 화면이 보임. UX 개선 필요.

### 변경 파일: `src/index.css`

```css
@keyframes fadeInUp {
  from { opacity: 0; transform: translateY(12px); }
  to   { opacity: 1; transform: translateY(0); }
}

@keyframes shimmer {
  0%   { background-position: -400px 0; }
  100% { background-position: 400px 0; }
}

.menu-card {
  /* 기존 속성들... */
  animation: fadeInUp 0.35s ease both;
  /* 주의: transform: translateZ(0) 제거 — animation의 transform과 충돌해 애니메이션 안 보이는 버그 */
}

.skeleton-card {
  border-radius: 12px;
  overflow: hidden;
  background: #e8e8e8;
  height: 220px;
  animation: shimmer 1.4s infinite linear;
  background-image: linear-gradient(90deg, #e8e8e8 25%, #f4f4f4 50%, #e8e8e8 75%);
  background-size: 800px 100%;
}

.app.dark .skeleton-card {
  background: #2a2a2a;
  background-image: linear-gradient(90deg, #2a2a2a 25%, #333 50%, #2a2a2a 75%);
}
```

### 변경 파일: `src/App.js`

- `recipeLoading` state 추가 (true → false, 첫 데이터 도착 시)
- `applyData()` 내부에서 `setRecipeLoading(false)` 호출
- 카드 렌더링 시 stagger delay 적용:

```jsx
<ul className="menu-list grid-list">
  {recipeLoading && sortedResults.length === 0 ? (
    Array.from({ length: 12 }).map((_, i) => (
      <li key={i} className="skeleton-card" style={{ animationDelay: `${i * 0.05}s` }} />
    ))
  ) : sortedResults.length > 0 ? (
    sortedResults.map((item, i) => (
      <RecipeCard
        key={item.url}
        {...makeCardProps(item)}
        style={{ animationDelay: `${Math.min(i, 11) * 0.04}s` }}
      />
    ))
  ) : (
    <p className="no-results">{t.noResults}</p>
  )}
</ul>
```

### 주의사항 (버그 이력)
`transform: translateZ(0)` (GPU 힌트)를 `.menu-card`에 정적으로 두면 `fadeInUp` 애니메이션의 transform과 충돌해 애니메이션이 보이지 않음. `will-change: transform`으로 대체.

## 작업 3: 유튜브 분석 프롬프트 개선

### 배경
- 레시피 순서가 너무 짧게 추출됨 ("데치기", "마무리" 수준)
- 레스토랑 소개 영상(아말피 코스트 피자, 거대한 꽃게 파스타 등)이 요리 영상으로 오분류되어 레시피 추출 시도됨

### 변경 파일: `youtube_automation.py`

**순서 상세화 (3개 프롬프트 모두 적용):**
```
순서는 각 단계를 1~2문장으로 작성하세요. 영상에서 언급된 온도·시간·양·핵심 포인트가 있으면 반드시 그대로 포함하세요
(예: "180도로 예열한 오븐에 10분 굽습니다", "약불에서 저으면서 3분 볶습니다").
단순 동사 하나("데치기", "마무리")만 쓰지 마세요.
"마무리", "완성", "플레이팅" 같은 의미 없는 단계는 금지하세요.
```

**레스토랑 영상 감지 (3개 프롬프트 모두 적용):**
```
크리에이터가 직접 요리하는 과정을 보여주는 영상만 분석하세요.
레스토랑 방문/소개, 음식점에서 주문해 먹는 영상, 음식 리뷰, 먹방, 식당 투어는 요리 영상이 아닙니다.
→ "분석 불가 (레스토랑 소개/먹방/음식 리뷰 등 직접 요리하지 않는 영상)"라고만 답하세요.
```

**에러 메시지 개선:**
```python
# 기존
"어떤 소스에서도 레시피를 찾지 못했습니다"

# 변경
"레시피를 찾을 수 없습니다. 직접 요리하는 영상이 아닌 경우(레스토랑 소개, 먹방, 음식 리뷰 등)는 분석이 어렵습니다."
```

### 한계
프롬프트 레벨 판단이라 경계가 모호한 영상(요리도 하고 식당도 가는 영상)은 여전히 오탐 가능성 있음.

## 작업 5: YouTube 레시피 추출 파이프라인 리팩터링

### 배경
채널 분석 테스트 중 Whisper(3순위)가 제대로 작동하지 않고, 오히려 Gemini 영상 분석(4순위)이 자주 실행됨을 발견.

### 문제 진단
테스트 영상 `https://www.youtube.com/watch?v=zGs0c86neWw` 분석:
- 고정댓글 → 재료 2개, 순서 0단계
- Whisper 전사 결과: `멍게 토마토 카펠리니 올리브오일 레몬오일 ・ぼんやり・すいもん` (34자)
- `len(text) > 50` 임계값에 막혀 None 반환 → Gemini 미트리거
- 원인: 영상에 말이 거의 없고, 임계값이 유효한 짧은 음성도 차단

### 변경 내용: `youtube_automation.py`

**최종 파이프라인 (기존 → 변경):**
```
기존:
1순위: 고정댓글 + 더보기란 + 자막 → Groq
2순위: Whisper 음성 → Groq
3순위: Gemini 2.5 Flash 영상 분석

변경:
1순위: 고정댓글 + 더보기란 → Groq (자막 제거)
2순위: Gemini 2.5 Flash 영상 분석 (품질 미달 시)
```

**Groq `target` 파라미터 추가:**
```python
ask_groq_from_text(text, source_name, target="both")
# target: "both" | "ingredients" | "steps"
# 부족한 항목만 요청 → 이미 확보된 항목은 덮어쓰지 않음
```

**Gemini 트리거 조건 변경:**
```python
# 기존: not all_results (완전 실패 시만)
# 변경: 재료 < 4개 OR 순서 < 3단계 (품질 미달 포함)
need_ingredients = len(cur_ingredients) < 4
need_steps = len(cur_steps) < 3
if need_ingredients or need_steps:
    → Gemini 영상 분석 실행
```

**Whisper 임계값 제거 (→ 최종 Whisper 자체 제거):**
- 기존: `return text if len(text) > 50 else None` — 짧은 유효 음성도 차단
- 임계값 제거 논의 중 → Gemini가 음성 포함 모든 정보를 보므로 Whisper 자체가 불필요 결론
