## 1. ingredients_measured 인덱스 어긋남 근본 수정

### 문제
`sortedData`에서 `recipeEdits`가 있으면 `ingredients`를 편집 버전(재배열 가능)으로 교체하는데,
`measuredRaw`는 DB 원본 인덱스 기준이라 인덱스가 어긋남.

예: DB `ingredients` = ["파스타","페스토","생크림"], 유저가 ["생크림","파스타","페스토"]로 재배열 후 저장
→ `ingMeasuredMap["생크림"] = "파스타 150~200g"` (인덱스 0끼리 매칭된 잘못된 값)

display `measuredAmountMap`도 동일한 index-based 방식이라 표시도 틀리고, 저장 시 `"생크림 파스타 150~200g"` 같은 이중 오염 발생.

### 해결 — 이름 prefix 기반 파싱으로 전환

`ingredients_measured` 각 항목이 `"재료명 용량"` 형식임을 이용.
`startsWith(ing.trim() + ' ')` 로 재료명 매칭 → 인덱스와 무관하게 정확한 맵핑.

**수정 위치 두 곳:**

```js
// sortedData (App.js ~1112)
(item.ingredients_measured || []).forEach(full => {
  if (!full) return;
  const matched = (item.ingredients || []).find(ing => full.startsWith(ing.trim() + ' '));
  if (matched) ingMeasuredMap[matched.trim()] = full;
});

// display measuredAmountMap (App.js ~2221)
(recipeModal.ingredients_measured || []).forEach(full => {
  if (!full) return;
  const matched = (recipeModal.ingredients || []).find(ing => full.startsWith(ing.trim() + ' '));
  if (matched) measuredAmountMap[matched.trim()] = full.slice(matched.trim().length + 1).trim();
});
```

**효과:** 기존 DB에 이미 어긋난 데이터도 올바르게 표시됨 (DB 수동 수정 불필요).

## 2. MY NOTE 기능 UX 전면 개선

### 기존 문제
- 위치: 모달 헤더 바로 아래 (레시피 내용보다 먼저 보임)
- 디자인: 날 textarea, 저장 피드백 없음
- 편집 종료: 모달 밖 클릭만 가능 (불편하고 모달 닫힘 위험)

### 변경 사항

**위치:** 모달 최하단 (GALLERY 섹션 이후) — 레시피 다 읽은 뒤 메모하는 자연스러운 흐름

**구조:**
```
MY NOTE              ← recipe-modal-section-title과 동일 스타일
┌─────────────────┐
│ 메모 추가...     │  ← 연한 배경 박스 (비편집 상태)
└─────────────────┘

편집 상태:
┌─────────────────┐
│ [textarea]      │
└─────────────────┘
                47/200  ✓
```

**편집 종료 방법 3가지:**
1. **✓ 버튼** — `onMouseDown` + `e.preventDefault()`로 blur보다 먼저 처리
2. **Escape 키** — `onKeyDown`에서 감지 후 저장 + 닫기
3. **blur** — 기존 안전망 유지

**모달 닫힘 방지:**
```js
// noteEditingRef (useRef) 패턴
onFocus={() => { noteEditingRef.current = true; }}
onBlur={() => { ...; setTimeout(() => { noteEditingRef.current = false; }, 150); }}
// Modal preventClose prop으로 전달
preventClose={() => noteEditingRef.current
```
blur→click 이벤트 간격(~5ms)을 150ms timeout으로 커버.

**화살표 키 충돌 해결:**
```js
// 키보드 네비게이션 핸들러에 추가
if (document.activeElement?.tagName === 'TEXTAREA' || ...'INPUT') return;
```

**북마크 탭 화살표 네비게이션:**
```js
const modalNavList = activeTab === 'saved'
  ? validRecipes.filter(item => savedRecipes.includes(item.url) && !deletedKeys.has(item.url))
  : sortedResults;
```
저장 탭에서는 북마크된 레시피 내에서만 ←→ 이동.

**북마크 카드 노트 미리보기:** 카드 아래 패널 → 우측 하단 📝 아이콘 뱃지로 대체.

## 3. 북마크 soft-delete (note 보존)

### 문제
북마크 해제 시 `bookmarks` row를 DELETE → `note` 컬럼도 삭제됨.
재북마크 시 메모 유실.

### 해결 — bookmarked boolean 컬럼 추가

**Supabase SQL:**
```sql
ALTER TABLE bookmarks ADD COLUMN IF NOT EXISTS bookmarked boolean DEFAULT true;
UPDATE bookmarks SET bookmarked = true WHERE bookmarked IS NULL;
```

**코드 변경:**

| 동작 | 기존 | 변경 |
|------|------|------|
| 북마크 해제 | `DELETE` | `UPDATE SET bookmarked = false` |
| 북마크 등록 | `INSERT` | `upsert + SET bookmarked = true` |
| 북마크 조회 | `select` | `select + eq('bookmarked', true)` |

**성능:** 1만 유저 × 50 북마크 = 50만 row, PostgreSQL 기준 인덱스로 충분. DELETE보다 UPDATE가 write 부하 낮음.

## 현재 아키텍처 (북마크/노트)

```
북마크 CRUD: supabase.from('bookmarks') 직접
- bookmarked=false: 해제 상태 (note 보존)
- bookmarked=true: 활성 북마크
note: blur / Escape / ✓버튼 시 supabase update
```
