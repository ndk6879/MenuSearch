## 1. Railway 완전 제거 — 레시피 편집 Supabase 직접 전환

### 배경
Railway Flask가 레시피 편집(PATCH /api/recipes)에만 남아있었음.
크리에이터 인증을 `X-Creator-Uid` 헤더로 하던 구조 → Supabase RLS로 전환.

### Supabase 설정

**creator_profiles 테이블 생성:**
```sql
CREATE TABLE creator_profiles (
  user_id uuid PRIMARY KEY REFERENCES auth.users(id),
  uploader text NOT NULL
);
INSERT INTO creator_profiles (user_id, uploader) VALUES
  ('037ff7ad-3aba-4ea5-b5cd-e078c4ac1248', '미뇨끼'),
  ('9ef8ac07-b566-4274-a694-3954354c2115', '이태리 파브리 Italy Fabri'),
  ('76d74b0e-e809-42cd-8af8-ae6f103e3a0d', '셰프호윤 Chef Hoyoon');

GRANT SELECT ON creator_profiles TO authenticated;
GRANT SELECT ON creator_profiles TO service_role;
ALTER TABLE creator_profiles DISABLE ROW LEVEL SECURITY;
```

**RLS 정책:**
```sql
CREATE POLICY "creators_update_own_recipes" ON recipes
FOR UPDATE TO authenticated
USING (
  uploader = (SELECT uploader FROM creator_profiles WHERE user_id = auth.uid())
);
```

**트러블슈팅:**
- 처음 시도한 `split_part(email, '@', 1)` 방식 실패 — uploader 값이 `'미뇨끼'`인데 이메일 prefix는 `'minyokki'`라 불일치
- creator_profiles에 RLS가 기본 활성화돼 있어 서브쿼리가 NULL 반환 → `DISABLE ROW LEVEL SECURITY`로 해결

### 코드 변경 (App.js)

`saveEditDraft`: fetch → supabase.update, **tip/servings 추가**
```js
supabase.from('recipes').update({
  name: updates.name,
  ingredients: newIngredients,
  ingredients_measured: newMeasured,
  steps: updates.steps,
  tips: updates.tip ? [updates.tip] : [],
  servings: updates.servings || '',
}).eq('url', recipeUrl)
```

`toggleHidden`: fetch → supabase.update
```js
supabase.from('recipes').update({
  status: newHidden ? 'hidden' : 'published',
}).eq('url', recipeUrl)
```
