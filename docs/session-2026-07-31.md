## 작업 1: 단계별 이미지 추출 파이프라인 구현

### 파이프라인 구조
```
YouTube URL
  → Gemini 1번 호출 (영상 직접 분석)
      ├── 재료
      ├── 요리 순서
      └── step_images: 시각적으로 중요한 단계 타임스탬프 (최대 4개)
  → yt-dlp -g: 영상 스트림 URL 추출 (다운로드 없음)
  → ffmpeg: 타임스탬프 ±4초 범위 7장 후보 프레임 추출 (bestvideo 포맷)
  → Gemini 2번 호출 (이미지 직접 비교)
      └── 후보 중 손/모션 없고 음식이 주인공인 최적 1장 선택
  → Supabase Storage: recipe-images/{video_id}/step_{n}.jpg 업로드
  → Supabase DB: recipes.step_images JSONB 저장
```

### 완성 요리 사진
- YouTube `maxresdefault.jpg` 썸네일을 완성 요리 사진으로 사용
- 크리에이터가 직접 선택한 고화질 컷, 별도 추출 불필요
- `step_images.dish` 키에 URL 저장

### 추가된 파일 및 함수

| 파일 | 추가 내용 |
|------|----------|
| `youtube_automation.py` | `get_best_thumbnail_url()`, `extract_step_frames()`, `upload_step_frames_to_supabase()`, `process_step_images()`, `_select_best_frame_with_gemini()` |
| `test_frame_extract.py` | 단독 테스트 스크립트 (로컬 저장 + 선택적 Supabase 업로드) |
| `supabase/migrations/20260731000001_add_step_images.sql` | recipes 테이블에 `step_images jsonb` 컬럼 추가 |

### Supabase 변경

- `recipes` 테이블: `step_images jsonb` 컬럼 추가

## 이미지 품질 개선 이력

| 시도 | 변경 내용 | 결과 |
|------|----------|------|
| 1차 | 타임스탬프 ±1초 3장, 선명도 기준 선택 | 손/모션 프레임 다수 |
| 2차 | Gemini Vision 2차 호출로 최적 프레임 선택 | 개선, 일부 손 잔존 |
| 3차 | `bestvideo` 포맷 + 정밀 시킹 (pre-seek 2초) | 파일크기 50KB→500KB+, 화질 대폭 향상 |

## 알려진 한계 및 향후 개선 과제

- **쇼츠 특성**: 카메라 움직임이 많아 정지 프레임 품질이 롱폼보다 낮음
- **자막 오버레이**: 쇼츠 자막이 이미지에 겹침 (현재로서는 허용)
- **프롬프트 튜닝**: 더 많은 영상 테스트 후 요리 순서 단계 수/길이 기준 정교화 필요
- **step_images 프롬프트**: 이미지가 필요한 단계 선정 기준 추가 개선 예정
