### 3. 카카오 로그인 버그 수정
**증상:** 카카오 인증 완료 후 메인 화면으로 돌아오는데 로그인 UI가 안 바뀜 (이름/프로필 미표시)

**원인:** 앱 마운트 시 `#access_token=...` URL hash를 즉시 제거하는 useEffect가 Supabase OAuth token을 먼저 지워버려 세션 수립 실패.

```js
// 삭제된 코드 (이게 문제였음)
useEffect(() => {
  if (window.location.hash.includes('access_token')) {
    window.history.replaceState(...); // Supabase가 읽기 전에 지워버림
  }
}, []);
```

**해결:** 해당 useEffect 삭제. `SIGNED_IN` 이벤트 핸들러의 hash 정리가 이미 올바른 타이밍에 동작함.

### 4. 북마크 Flask → Supabase 직접 호출 전환
**기존:** 북마크 CRUD → Railway Flask `/api/bookmarks` → Supabase REST
**변경:** `supabase.from('bookmarks')` 직접 호출

**이유:** Railway 단일 장애점 제거, 수동 배포 불필요, 속도 향상

**RLS 설정 (Supabase SQL Editor에서 실행):**
```sql
ALTER TABLE bookmarks ADD COLUMN IF NOT EXISTS note text;

CREATE POLICY "users_own_bookmarks" ON bookmarks
FOR ALL TO authenticated
USING (auth.uid()::text = user_id)
WITH CHECK (auth.uid()::text = user_id);
```

**bookmarkUid:** 크리에이터는 `creator:minyokki` 문자열 대신 실제 Supabase UUID 사용
```js
const bookmarkUid = socialUser?.uid || creatorUser?.supabaseId || null;
```
- `_applySession`에서 `creatorUser.supabaseId = user.id` (UUID) 저장
- `creatorUser.uid = 'creator:minyokki'`는 X-Creator-Uid 헤더용으로 유지

### 7. 재료 편집 저장 시 ingredients_measured 인덱스 어긋남 수정
**증상:** 크리에이터가 재료 편집 저장 후 RECIPE 섹션에서 재료명과 용량이 한 칸씩 밀림
(예: "생크림" 칩에 "파스타 150~200g" 표시)

**원인:** `saveEditDraft`가 `ingredients`만 PATCH하고 `ingredients_measured`는 갱신 안 함 → 인덱스 어긋남

**해결:**
- `measuredAmountMap`(재료명→용량 맵)을 `onSave` 콜백에서 `saveEditDraft`로 전달
- PATCH body에 `ingredients_measured` 포함
- `api_server.py` allowed 필드에 `ingredients_measured` 추가

## 트러블슈팅

| 에러 | 원인 | 해결 |
|------|------|------|
| 북마크 INSERT RLS 오류 | anon 키로 INSERT 시도, 정책 없음 | authenticated 정책 추가 |
| 북마크 다른 기기에서 안 보임 | INSERT 실패로 Supabase에 실제 저장 안 됨 (optimistic update만) | RLS 정책 + UUID 기반 user_id |
| 카카오 로그인 후 UI 안 바뀜 | 앱 마운트 hash 정리가 Supabase token보다 먼저 실행 | hash 정리 useEffect 삭제 |
| 크리에이터 로그인 폼 고착 | LoginModal state가 마운트 유지로 리셋 안 됨 | open 변경 시 state 초기화 |
